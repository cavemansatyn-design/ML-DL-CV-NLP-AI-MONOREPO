## A. Logistic regression and breast-cancer classification

The notebook has two connected components.

### Parameter estimation
- Implements logistic-regression parameter estimation using maximum likelihood estimation (MLE) and maximum a posteriori (MAP).
- Explores how the likelihood and prior contribute to parameter estimation.
- Uses the logistic link to convert a linear score into a probability.

### Diagnostic classification workflow
1. Loads the built-in breast-cancer diagnostic dataset.
2. Examines class distribution and predictor relationships.
3. Checks multicollinearity.
4. Performs train/test splitting and feature scaling.
5. Fits a baseline logistic-regression classifier.
6. Extracts coefficients and converts them to odds ratios for interpretation.
7. Evaluates the default probability threshold of 0.5.
8. Tests custom thresholds to study the precision/recall trade-off.

**How to interpret it:** a coefficient describes the change in log-odds for a one-unit predictor change, conditional on the other model inputs. Exponentiating a coefficient gives its odds ratio. A threshold change alters the predicted class decisions without retraining the underlying probability model.

**Metrics availability:** the notebook file contains the implementation and analysis sections, but its saved version does not retain printed numerical output cells for final accuracy, precision, recall, F1 or confusion-matrix values. Those numbers should be generated by running the notebook; they are intentionally not guessed in this README.

## B. Regression model comparison and gradient boosting

### Dataset and exploratory analysis
- 873 rows, 22 columns and 291 groups; each group has three rows.
- Raw columns: `row_id`, `group_id`, `F1`–`F19` and `target`.
- 16 numerical predictors and three categorical predictors (`F13`, `F14`, `F15`).
- Target mean 754.99, standard deviation 638.05, median 595, range 0–3285.
- 97 rows (11.1%) contain at least one missing value; no column exceeds 1.83% missingness.
- Strongest reported numerical Pearson correlations with target: F19 +0.471, F4 −0.458, F16 +0.339, F12 +0.272 and F11 −0.226. These are associations, not causal effects.

### Data preparation and feature engineering
- Excludes `row_id` and `group_id` from model predictors; `group_id` remains available for splitting and diagnostics.
- Median-imputes numerical columns and adds missingness indicators.
- Imputes categorical columns with the most frequent category.
- One-hot encodes F13, F14 and F15; unknown categories are ignored.
- Produces 38 model features: 16 numerical values, 8 missingness indicators and 14 one-hot indicators.
- Checks transformed data for NaNs and checks that identifier columns are excluded.

### Validation design
`GroupShuffleSplit(test_size=0.20, random_state=2024514)` creates 696 training rows and 177 validation rows while keeping each group intact. This is more appropriate than a random row split when evaluation concerns unseen groups. It is one split, so results may vary with the held-out groups.

### Model results

| Model | Train R² | Validation R² | Validation RMSE | Validation MAE |
|---|---:|---:|---:|---:|
| Histogram Gradient Boosting | 0.9569 | **0.8802** | **221.22** | **154.84** |
| Linear Regression | 0.7493 | 0.7543 | 316.87 | 233.30 |
| Lasso (α=0.01) | 0.7493 | 0.7543 | 316.87 | 233.30 |
| Ridge (α=0.01) | 0.7493 | 0.7543 | 316.88 | 233.31 |
| Elastic Net | 0.7455 | 0.7476 | 321.16 | 236.42 |

Histogram Gradient Boosting improves validation R² by 0.1259 over the linear baseline and reduces RMSE by 95.65 and MAE by 78.46. Its train–validation R² gap is approximately 0.0767, so the stronger fit also has a larger generalisation gap.

### Diagnostics and limitations
- Target distribution is right-skewed; large targets are harder to estimate.
- The baseline tends to pull extreme target values toward the middle.
- F10 shows a nonlinear relationship with the target; a quadratic term is proposed as a follow-up experiment.
- The report notes preprocessing is fitted before the train/validation split in the current implementation. This allows validation feature-distribution information into imputation/encoding, though not validation labels. A stricter pipeline should fit preprocessing on training groups only.
- Scores are internal validation results, not hidden-test results.

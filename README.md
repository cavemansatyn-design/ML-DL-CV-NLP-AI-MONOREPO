# 01 — Supervised Machine Learning

## 01.1 — Logistic regression and breast-cancer diagnostic classification

**Notebook:** `01-ML-Supervised/01-Classification-Regression/logistic-regression-breast-cancer.ipynb`

### Objective and workflow
This project studies logistic regression from both an estimation and applied-classification perspective.

- **Parameter estimation:** implements maximum likelihood estimation (MLE) and maximum a posteriori (MAP) estimation for logistic-regression parameters. The saved notebook provides the estimation workflow; no final numeric likelihood, coefficient-error or parameter-recovery benchmark is retained.
- **Dataset:** uses scikit-learn's built-in Breast Cancer Wisconsin diagnostic dataset. The notebook loads and explores the feature and class structure; the repository README does not infer a new dataset count or split size beyond what is preserved in the notebook.
- **Exploratory analysis:** examines class distribution and relationships among predictors. No standalone numeric EDA score is retained.
- **Multicollinearity:** checks correlations among predictors before fitting. No single numeric multicollinearity statistic is preserved as a final result.
- **Preprocessing:** performs train/test splitting and feature scaling before model fitting. The exact saved split and random seed should be read from the notebook execution cells.
- **Model interpretation:** extracts logistic-regression coefficients and exponentiates them to obtain odds ratios. An odds ratio expresses the multiplicative change in odds for a one-unit increase in a predictor, conditional on the other model inputs.
- **Decision threshold:** evaluates the default probability threshold of 0.5 and experiments with custom thresholds to inspect the precision/recall trade-off.

### Quantitative results

| Final accuracy | Not retained in saved output cells |
| Precision / recall / F1 | Not retained in saved output cells |
| Confusion matrix | Not retained as a persisted final numeric result |
| MLE / MAP final parameter benchmark | No final numeric benchmark retained |
| Threshold comparison | Implemented; numerical comparison must be regenerated by running the notebook |

**Interpretation:** the project demonstrates probability estimation, coefficient interpretation and threshold-dependent classification. It would be misleading to attach an accuracy or F1 score that is not present in the saved outputs.

## 01.3 — Spoken-digit recognition with an RBF SVM

**Notebook:** `01-ML-Supervised/02-Audio-Traffic/spoken-digit-svm (ML_A3.zip).ipynb`  
**Report:** `01-ML-Supervised/02-Audio-Traffic/audio-traffic-report.pdf`

### Dataset and feature representation
- Training data: **2,000 audio clips**.
- Validation data: **500 audio clips** from held-out speaker **S5**.
- Input representation: **53 acoustic features**.
- Training speakers: **S1–S4**; validation speaker: **S5**.
- Audio format described in the report: **8 kHz, mono**.
- Clip duration range: **0.22–1.00 seconds**.
- Reported feature standard-deviation range: **0.1530–44.8118**.

### Experiments and metrics
| Experiment | Evaluation | Result |
|---|---|---:|
| Standardised 53-feature RBF SVM | Held-out speaker S5, 500 clips | **73.00% accuracy** |
| All-feature model | Leave-One-Speaker-Out (LOSO) | **50.85%** |
| Speaker-robust 34-feature selection | Held-out speaker S5 | **82.00% accuracy** |
| Selected 34-feature model | LOSO | **49.50%** |
| Unscaled feature baseline | Reported validation comparison | **17.20% accuracy** |

- Feature selection raises the S5 result from **73% to 82%**, an improvement of **9 percentage points**.
- The selected-feature LOSO result is **1.35 percentage points lower** than the all-feature LOSO result (49.50% versus 50.85%). This is an important distinction: the S5 validation gain does not imply that every speaker-independent evaluation improves.
- Standardisation is consequential: the unscaled comparison reports **17.20%**, compared with **73.00%** for the standardised 53-feature model.
- The baseline model misclassifies **135 of 500** S5 validation clips.
- Digits **1** and **6** are the easiest reported classes at **98%** each. Digits **0** and **8** are identified as harder classes; exact per-class values are not asserted here.

### Interpretation
The gap between ordinary cross-validation and speaker-independent evaluation illustrates speaker leakage: clips from the same speaker can share acoustic characteristics. The report records stratified five-fold accuracy of **90.50% ± 0.96%**, but this should not be interpreted as unseen-speaker generalisation. The more relevant speaker-aware figures are LOSO (**50.85%** and **49.50%**) and held-out S5 (**73%** and **82%**).

A hidden-test performance of approximately **80–82%** was discussed as a prediction, not measured evidence; it is therefore not presented as an achieved metric.

## 04.3 — ARC-AGI-1-style symbolic grid reasoning

**Notebook:** `04-Classic-AI/03-ARC-Reasoning/arc-agi-solver (ARC JSON required).ipynb`

### Solver workflow
- Represents coloured grids as matrices of integer colour values.
- Extracts connected components using four-neighbour connectivity.
- Generates a fixed library of candidate transformations.
- Scores candidate transformations against demonstration input/output pairs.
- Ranks candidate rules and applies the selected transformation to test inputs.

### Candidate transformation library
The notebook includes:
- identity;
- 90°, 180° and 270° rotations;
- horizontal reflection;
- vertical reflection;
- transpose;
- crop-to-content.

### Local test coverage and metric status
- Includes constructed toy checks for a **two-cell connected object**.
- Checks a **90-degree rotation** result.
- Checks demonstration-based candidate ranking and prediction output.
- These are unit-style correctness checks on constructed examples, not a benchmark over official ARC tasks.
- No official ARC task count, solve rate, accuracy or generalisation score is claimed because no ARC JSON task dataset is bundled.

### Limitations
The solver uses a small fixed set of global transformations. It does not claim coverage of tasks requiring object counting, conditional logic, multi-object relations, drawing, symmetry completion, identity-dependent colour mapping or compositions of multiple operations. It assumes background colour **0** and four-neighbour connectivity.

## Evaluation notes and limitations

- **Classification metrics:** accuracy, precision, recall and F1 depend on class balance and threshold. Macro-F1 weights classes equally and should not be confused with accuracy.
- **Regression metrics:** R² measures explained variance relative to a constant-mean baseline; RMSE penalises large errors more strongly than MAE.
- **Clustering metrics:** silhouette evaluates geometric separation; ARI and NMI compare cluster assignments with reference labels. Reference labels are used for evaluation only in the unsupervised tasks.
- **Validation design matters:** speaker-aware and time-aware splits are more representative of unseen-speaker and future-time deployment than random splits when the data have those structures.
- **Pending means pending:** no score is supplied for a run whose required dataset was unavailable or whose final outputs were not retained.
- **Classical AI benchmark gaps:** the truck-planning, Robo-Football and ARC notebooks contain algorithms and tests, but not complete saved quantitative benchmark tables. Their performance should be measured by rerunning controlled experiments.
